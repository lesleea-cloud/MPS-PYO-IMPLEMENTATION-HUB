Needs Attention Panel — Enhanced Alert Logic ✅ Coded
The Needs Attention panel was redesigned from a simple two-section list (Overdue / Upcoming) into a fully prioritized alert feed covering all key implementation phases — not just live run.
New Alert Types
PriorityColorTriggerBadge
0#dc2626Live run date passed but live phase not tickedOverdue
1#dc2626KOM done but Simulation not started — 15+ days idleOverdue
2#dc2626Simulation done but Parallel Run not started — 15+ days idleOverdue
3#ea580cLive run date within 7 daysX days
4#f59e0bLive run date within 8–14 daysX days
5#2563ebKOM done, Simulation not yet scheduled (no live run date)Schedule
6#2563ebSimulation done, Parallel Run not yet scheduledSchedule
What Was Removed
  • Section sub-headers ("OVERDUE", "UPCOMING — LIVE RUN", etc.) — redundant since each row badge communicates the same thing
  • "On track" / "All clear" section — only projects needing action appear
  • Completed projects (all 5 phases done) are excluded entirely
  • Churned projects are excluded
New Row Anatomy
  • Colored dot — urgency color at a glance
  • Client name — bold
  • Sub-text — plain-language description of the issue
  • Date line — the relevant date highlighted in color if overdue
  • Right column: Badge (Overdue / X days / Schedule) · Phase tag · Days label (Xd past / Xd idle)
New CSS Classes Added

.impl-attn-sublbl
JS Function Updated
implRenderAttention(myD) — fully rewritten. Builds a flat alerts[] array sorted by priority (0 = most urgent). Skips completed clients (all 5 phase flags ticked) and churned clients. Updates #impl-attn-count badge and shows/hides #impl-attn-legend.
Known Limitation — Priority 2: Priority 2 (Simulation done, Parallel Run 15+ days idle) is gated on d.simDate. Since simDate was not yet in the data schema, this alert does not fire until simDate is added. No code change needed — the alert activates automatically once simDate is populated.
